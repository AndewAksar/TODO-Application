# SECURITY_BASELINE

Документ описывает **текущее состояние реализации безопасности**.

Это **не политика**, а фиксация **фактических технических решений**, реализованных на данный момент.

---

## 1. JWT

- **Алгоритм:** `HS256`
- **Secret:** загружается из environment variable `JWT_SECRET_KEY`
- **TTL:** 60 минут
- **Refresh tokens:** отсутствуют
- **Blacklist / revoke:** отсутствует
- **`sub`:** строковое представление `user_id`
- **Payload:**
  - `sub`
  - `iat`
  - `exp`

---

## 2. Пароли

- **Алгоритм:** `bcrypt`
- **Реализация:** `passlib.CryptContext`
- **Соль:** генерируется автоматически
- **Cost-factor:** значение по умолчанию библиотеки
- **Хранение:**
  пароли сохраняются **только** в поле `password_hash`

---

## 3. База данных

- `users.id` — `int`
- `email` — `unique`
- `username` — `unique`, `nullable`
- **Soft-delete:** отсутствует
- **Блокировка пользователя:** отсутствует

---

## 4. Ограничения текущей модели

На текущий момент **не реализованы**:

- refresh-token механизм;
- rotation JWT secret;
- multi-device session management;
- rate limiting;
- защита от brute-force атак.

---

## 5. Threat Model (минимальный)

### 5.1 Предполагаемые угрозы

- попытка подбора пароля;
- попытка подмены JWT;
- повторное использование токена;
- логическая ошибка в dependency.

### 5.2 Не покрываются

- распределённые атаки;
- инфраструктурные атаки (DDoS);
- компрометация хоста.
