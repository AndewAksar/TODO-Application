# ADR-0006: AI Agent Integration Model

## Status
Proposed

## Context

В проекте используется AI-ассистент для:
- анализа кода,
- генерации изменений,
- написания тестов и документации.

AI-агент рассматривается не как "подсказчик",
а как потенциальный участник процесса разработки,
чьи действия должны быть ограничены и воспроизводимы.

Необходимо зафиксировать текущую модель интеграции
и целевое направление её развития.

## Current State (As-Is)

На данный момент:

- AI-агент используется в режиме "исполнитель по инструкции".
- Контекст агента ограничивается явным набором файлов.
- Изменения, предложенные агентом, проходят стандартный PR-процесс.
- Агент не имеет прямого доступа к:
  - секретам,
  - production-конфигурации,
  - инфраструктурным ключам.
- Поведение агента регулируется документом AGENTS.md.
- CI выполняет роль внешнего валидатора действий агента.

## Target State (To-Be)

Целевая модель:

- AI-агент рассматривается как **ограниченный контрибьютор**.
- Для агента явно определяются:
  - Writable зоны
  - Read-only зоны
  - Non-scope зоны
- Агент работает строго в рамках:
  - AGENTS.md
  - policies
  - контрактов задачи (task brief)
- Все изменения агента:
  - вносятся через Pull Request
  - проходят обязательный CI
  - не могут обходить quality gates

## Explicit Non-Goals

В рамках текущей модели **не планируется**:

- Автоматический merge изменений от агента.
- Прямой push в main или protected branches.
- Доступ агента к secrets или production credentials.
- Использование агента для runtime-операций в production.
- Делегирование архитектурных решений агенту без участия человека.

## Alternatives Considered

1. Полный доступ агента к репозиторию — отклонено (высокие риски).
2. Использование агента без формальных ограничений — отклонено (невоспроизводимость).
3. Полный отказ от AI-агентов — отклонено (потеря эффективности).

## Consequences

Плюсы:
- Контролируемое использование AI.
- Снижение риска неконтролируемых изменений.
- Совместимость с CI и governance-моделью.
- Возможность масштабирования использования агента.

Минусы:
- Дополнительная дисциплина при формировании задач.
- Более высокая сложность процесса разработки.

## Open Questions

- Требуется ли отдельный CI-профиль для agent-generated PR?
- Нужно ли маркировать agent PR отдельным label?
- Нужны ли отдельные policies для разных типов агентов?
