# ADR-0001: Repository Governance Model

## Status
Accepted

## Context

Проект развивается как многосервисное приложение с:
- CI/CD
- требованиями к качеству кода
- использованием AI-агентов
- потенциальным масштабированием команды

Необходим управляемый и воспроизводимый процесс внесения изменений.

## Decision

Принята модель строгого repository governance:

- Все изменения вносятся только через Pull Request.
- CI является обязательным quality gate.
- Используется CODEOWNERS для явного закрепления ответственности.
- Шаблон PR обязателен.
- Политики фиксируются в документах, CI является их исполняемой формой.

## Alternatives Considered

1. Прямые коммиты в main — отклонено (высокий риск регрессий).
2. CI как рекомендательный механизм — отклонено (нет гарантий качества).
3. Упрощённая модель без формализации — отклонено (плохо масштабируется).

## Consequences

Плюсы:
- Контролируемость изменений.
- Готовность к росту команды.
- Безопасная интеграция AI-агентов.

Минусы:
- Увеличение накладных расходов на изменения.
- Более высокий порог входа.
