# ADR-0004: Primary Key Strategy — Integer IDs

## Status
Accepted

## Context

Необходимо определить стратегию идентификаторов для основных сущностей (users, tasks).

## Decision

Выбраны автоинкрементные integer primary keys.

Причины:
- Простота.
- Производительность.
- Лёгкость работы с БД.
- Удобство интеграции с JWT (sub как строка числа).

## Alternatives Considered

1. UUID — отклонено (избыточно для текущего масштаба).
2. Composite keys — отклонено (усложняет модель).

## Consequences

Плюсы:
- Простота схемы.
- Высокая производительность индексов.
- Предсказуемость.

Минусы:
- Менее удобны для глобально распределённых систем.
- Сложнее миграция на UUID в будущем.
