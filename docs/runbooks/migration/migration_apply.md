# Migration Apply Runbook

## 1. Назначение

Этот runbook описывает **операции применения миграций базы данных**.

Документ используется при:

- запуске приложения на новой базе
- обновлении схемы БД
- запуске CI
- деплое приложения
- проверке согласованности схемы

Runbook реализует правила:

```
docs/policies/MIGRATION_POLICY.md
```

---

# 2. Основной принцип

Миграции являются **единственным источником изменений схемы БД**.

Схема базы данных **обязана соответствовать текущей ревизии миграций**.

Любое состояние БД должно быть достижимо через:

```
alembic upgrade
```

---

# 3. Canonical команда применения миграций

Применение миграций выполняется через Makefile.

```
make migrate
```

Команда выполняет:

```
alembic upgrade head
```

Это приводит схему БД к **последней ревизии**.

---

# 4. Проверка текущей версии схемы

Для проверки текущей версии схемы используется:

```
alembic current
```

Пример вывода:

```
Current revision(s) for postgresql://...:
1c9c115cdf19
```

Это означает, что база находится на указанной ревизии.

---

# 5. Проверка доступных миграций

Для просмотра истории миграций используется:

```
alembic history
```

Пример:

```
<base> -> 1c9c115cdf19 (head)
```

Это означает, что текущая ревизия является последней.

---

# 6. Применение конкретной ревизии

Иногда требуется применить миграции **не до head**, а до определённой ревизии.

Пример:

```
alembic upgrade <revision>
```

Это приводит схему к указанной версии.

---

# 7. Откат миграции

Откат выполняется командой:

```
alembic downgrade -1
```

Это откатывает последнюю миграцию.

Можно откатиться до конкретной ревизии:

```
alembic downgrade <revision>
```

---

# 8. Проверка миграций на чистой базе

Для гарантии корректности всей цепочки миграций рекомендуется периодически проверять их на чистой базе.

Процедура:

1. удалить базу данных
2. создать новую
3. выполнить

```
alembic upgrade head
```

Это проверяет:

- корректность всей истории миграций
- отсутствие зависимостей от текущего состояния БД

---

# 9. CI-проверка миграций

CI pipeline обязан проверять корректность миграций.

Минимальная проверка:

```
alembic upgrade head
```

на чистой базе.

Цель проверки:

- убедиться, что все миграции применяются
- убедиться, что схема БД соответствует коду

CI обязан падать если:

- миграции не применяются
- возникают ошибки схемы

---

# 10. Типовые ошибки

## 10.1 База не на последней ревизии

Симптом:

```
alembic current
```

показывает ревизию ниже `head`.

Решение:

```
alembic upgrade head
```

---

## 10.2 Ошибка применения миграции

Причины:

- конфликт типов
- нарушение ограничений
- несогласованность downgrade

Решение:

- проверить migration script
- исправить ошибки
- повторно применить миграцию

---

## 10.3 Конфликт ревизий

Иногда появляются **несколько head**.

Проверка:

```
alembic heads
```

Если heads несколько, необходимо выполнить merge migration.

---

# 11. Проверка после применения

После применения миграций необходимо:

1. убедиться, что приложение запускается
2. проверить логи
3. проверить основные запросы

---

# 12. Definition of Done

Миграция считается успешно применённой, если:

- команда `alembic upgrade head` завершилась без ошибок
- версия БД соответствует `head`
- приложение запускается корректно
- CI pipeline проходит успешно
