# Migration Debugging Runbook

## 1. Назначение

Этот runbook описывает **диагностику и устранение проблем системы миграций**.

Документ используется когда:

- миграции не применяются
- Alembic не видит конфигурацию
- возникает несколько `head`
- схема БД не соответствует коду
- миграции создаются внутри контейнера
- CI падает на проверке миграций

Runbook реализует правила:

docs/policies/MIGRATION_POLICY.md

---

# 2. Базовая диагностика

Перед любым исправлением необходимо проверить состояние системы миграций.

### Проверка текущей ревизии

```
alembic current
```

Показывает текущую версию схемы базы данных.

---

### Проверка последней ревизии

```
alembic heads
```

Показывает последнюю доступную ревизию.

---

### Проверка истории миграций

```
alembic history
```

Позволяет увидеть полную цепочку миграций.

---

### Проверка применения миграций

```
alembic upgrade head
```

Если команда завершается успешно — миграции применяются корректно.

---

# 3. Типовые проблемы

---

## 3.1 Alembic не установлен

Симптом:

```
No module named alembic
```

Причина:

- Alembic не установлен в контейнере
- Alembic отсутствует в dev-зависимостях

Проверка:

```
python -m alembic --version
```

Решение:

- добавить Alembic в dev/tooling зависимости
- пересобрать tooling container

---

## 3.2 Alembic не видит конфигурацию

Симптом:

```
No config file 'alembic.ini'
```

Причина:

- неправильная рабочая директория
- отсутствует файл `alembic.ini`

Проверка:

```
ls
```

Файл `alembic.ini` должен находиться в корне migration environment.

---

## 3.3 Миграции не применяются

Симптом:

```
alembic upgrade head
```

завершается ошибкой.

Причины могут быть:

- ошибка SQL
- конфликт ограничений
- несовместимость типов

Решение:

- проверить migration script
- исправить ошибку
- повторно выполнить upgrade

---

## 3.4 Несколько head

Симптом:

```
alembic heads
```

возвращает несколько ревизий.

Причина:

- несколько веток миграций
- параллельные изменения схемы

Решение:

создать merge migration:

```
alembic merge -m "merge heads" <rev1> <rev2>
```

---

## 3.5 Migration file не появился

Симптом:

```
alembic revision -m "..."
```

отработал успешно, но файла нет в репозитории.

Причина:

- миграция создана внутри ephemeral container
- отсутствует bind mount проекта

Проверка:

```
git status
```

Если файл отсутствует — workflow нарушен.

Решение:

использовать canonical workflow генерации миграций.

---

## 3.6 База данных не соответствует коду

Симптомы:

- приложение падает при старте
- отсутствуют таблицы
- несовпадают колонки

Проверка:

```
alembic current
```

Если ревизия не совпадает с `head`, необходимо выполнить:

```
alembic upgrade head
```

---

# 4. Проверка схемы на чистой базе

Если проблемы неочевидны, рекомендуется проверить миграции на пустой базе.

Процедура:

1. удалить базу
2. создать новую
3. выполнить

```
alembic upgrade head
```

Если цепочка миграций проходит — проблема была в состоянии БД.

---

# 5. Проверка контейнерной среды

При использовании Docker необходимо проверить:

- установлен ли Alembic
- доступен ли `alembic.ini`
- используется ли bind mount проекта

Проверки:

```
python -m alembic --version
```

```
ls migrations
```

```
ls migrations/versions
```

---

# 6. Проверка CI

Если CI падает на миграциях, необходимо проверить:

- создаётся ли база данных
- применяются ли миграции
- соответствует ли схема текущему коду

CI должен выполнять:

```
alembic upgrade head
```

на чистой базе.

---

# 7. Definition of Done

Проблема считается устранённой, если:

- `alembic upgrade head` выполняется без ошибок
- ревизия БД соответствует `head`
- приложение запускается
- CI pipeline зелёный

---

# 8. Расширенное объяснение (для разработчиков)

Система миграций состоит из трёх компонентов:

1. **Миграционные файлы**
2. **Конфигурация Alembic**
3. **Состояние базы данных**

Проблемы почти всегда возникают из-за рассинхронизации этих компонентов.

---

## 8.1 Рассинхронизация схемы и кода

Самая распространённая проблема.

Сценарий:

- модель изменена
- миграция не создана
- приложение ожидает новую схему

В результате:

- таблица отсутствует
- колонка отсутствует
- индекс отсутствует

Решение — создать миграцию и применить её.

---

## 8.2 Рассинхронизация базы и миграций

Сценарий:

- миграция существует
- база не обновлена

Проверка:

```
alembic current
```

Если ревизия ниже `head`, необходимо выполнить upgrade.

---

## 8.3 Проблема ephemeral container

Это типичная проблема Docker workflow.

Сценарий:

1. контейнер создаёт migration file
2. файл остаётся внутри контейнера
3. в репозитории файла нет

Контейнер при этом может быть удалён.

Результат:

- миграция потеряна
- код и база расходятся

Поэтому MIGRATION_POLICY требует:

- generation через tooling container
- bind mount проекта

---

## 8.4 Несколько head

Это возникает когда:

- два разработчика создают миграции параллельно
- ветки объединяются

Alembic создаёт несколько head.

Это не ошибка, но требует merge migration.

---

## 8.5 Почему CI проверяет миграции

CI выполняет:

```
alembic upgrade head
```

на чистой базе.

Это гарантирует:

- миграции воспроизводимы
- schema evolution корректна
- новая база может быть создана с нуля

Без этой проверки миграции могут ломаться незаметно.
