# JWT Secret Rotation Runbook

## 1. Назначение

Описывает безопасную ротацию JWT-секрета без немедленного разрыва клиентских сессий.

---

## 2. Ограничения текущей архитектуры

Текущая модель:
* один JWT-секрет
* нет refresh tokens
* нет revoke / blacklist

Следствие:
* смена секрета инвалидирует все старые токены

---

## 3. Стратегии ротации

### Вариант 1 — Жёсткая ротация

* меняется секрет
* все пользователи перелогиниваются

Допустимо:
* только для dev
* ранний этап проекта

---

### Вариант 2 — Двойная валидация (рекомендуется)

Принцип:
* `encode` → **новый** секрет
* `decode` → **[новый, старый]**

Требования:
* `decode_token` принимает список ключей
* `create_access_token` всегда использует активный ключ

---

## 4. Процедура ротации (двойная валидация)

Шаги:
1. Добавить новый секрет в окружение (`JWT_SECRET_KEY_NEXT`)
2. Обновить код:
   * encode → новый ключ
   * decode → `[новый, старый]`
3. Выполнить деплой
4. Выдержать grace-period ≥ TTL токена (рекомендуется `2 × TTL`)
5. Удалить старый ключ из decode-списка
6. Удалить старый секрет из окружения

---

## 5. Контроль и тесты

Обязательные проверки:
* токен, выпущенный новым секретом, валиден
* токен, выпущенный старым секретом, валиден в grace-period
* после grace-period старый токен → `401`

---

## 6. Риски и запреты

Запрещено:
* хранить секреты в коде
* писать секреты в логи
* делать бесконечный grace-period

Бесконечный grace-period = уязвимость.
